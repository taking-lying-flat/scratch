# Casebook 终稿审校

以源码证据和可复现结果为准，对正文、GitHub 文件页与可选 Pages 页面执行终稿检查。用户要求修改时直接修复确定的问题；用户只要求评审时按影响排序报告问题及位置。

## 内容与文风

确认标题、范围与结论一致，因果链没有状态跳跃，事实、推导和假设能够区分，修复方案对应已确认根因。逐项核对版本、标识符、shape、dtype、单位、索引域、源码永久链接和日志语义。删除口语、反问、空泛修饰和重复结论；检索并消除 `不是……而是……` 与 `……而不是……` 句式。同一因果环节应形成完整段落，连续短句和单句段落应合并，严格并列信息才保留为列表。

## 呈现与验证

确认关键不变量、阶段结论和风险已经使用语义匹配的 GitHub alert，高亮数量由内容决定；避免重复高亮与连续堆叠。禁止 `<details>` 和正文折叠。检查每个图示是否比正文或表格提供更多有效信息，并遵守用户对图示的取舍；同时检查 Mermaid、图片、表格、代码块、目录、heading anchor 与相对链接。存在 Pages 前端时还要执行静态构建并检查项目 base path、响应式布局、深浅主题、代码与宽表溢出。

运行技能验证器、`git diff --check` 和可用的 Markdown link checker。若仓库提供 lint、构建或预览命令，也要运行对应检查。交付说明列出已验证项目、仍缺少的外部证据和未执行检查的原因。
